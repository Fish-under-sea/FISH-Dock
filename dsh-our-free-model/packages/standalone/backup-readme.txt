FISH Dock · OFM 配置与凭据迁移说明

一、安全提示
此 ZIP 未加密，包含 OFM 账号凭据、EAC 授权、本机 API Key、LAN Key 和服务配置。
请按密码文件保管，不要上传到 GitHub、工单、聊天群、网盘公共链接或日志。
只在可信设备之间传输。完成迁移后删除不再需要的明文副本。
本备份不包含 DSH 凭据库、FISH Dock 外观配置、浏览器资料、聊天记录或调用统计。

二、适用范围
适用于 FISH Dock 1.0.0 的 OFM 独立服务，以及兼容相同数据格式的后续版本。
未包含的软件升级、浏览器登录环境和供应商设备绑定不能通过本 ZIP 复制。
迁移后部分账号可能过期、被撤销或要求重新授权，不代表备份损坏。

三、迁移步骤
1. 在目标设备安装 FISH Dock，并从托盘完全退出源设备和目标设备上的 FISH Dock。
2. 备份目标设备已有的 OFM 数据目录。默认目录为 %USERPROFILE%\.dsh-fish；
   若通过运行环境指定了其他目录，以该设备的 OFM 实际数据目录为准。
   不要把这些文件复制到 FISH Dock 的安装目录、WebView2 目录或 DSH 的主目录。
3. 将本 ZIP 的 settings.json、channel-credentials.json、channel-pack 文件夹，
   以及存在时的 eac-user.json 复制到目标 OFM 数据目录的相同相对位置。
   如目标已有同名文件，确认保留目标备份后再替换；此操作是替换，不是合并账号。
   channel-pack/accounts-backup.json 是额外的账号快照，运行时不会自动导入它。
4. README.txt 和 manifest.json 用于说明与完整性核对，无需复制到数据目录。
5. 启动 FISH Dock，检查 OFM 账号、模型开关和 EAC 授权。失效账号需重新登录。
6. 检查服务端口、LAN 开关与当前设备的实际局域网地址。备份会保留 LAN 开关，
   首次迁移启动前应确认目标网络可信；无需共享时可在启动前将 settings.json 中
   standaloneLanEnabled 改为 false。防火墙、路由和设备地址不会随备份迁移。
7. 本机 API Key 和 LAN Key 也随设置迁移。若不希望两台设备共用密钥，请在目标
   设备分别轮换两类密钥，并更新相应客户端；LAN Key 不授予管理页面权限。

四、验证与缺项
manifest.json 记录每个文件的字节数与 SHA-256，以及未能读取的账号凭据数量。
该清单用于检测传输损坏，不是数字签名，也不能证明文件来源可信。
缺少 eac-user.json 表示导出时没有可迁移的 EAC 本地授权。
缺失凭据不会由此备份重建，仍需在目标设备重新授权。
若不确定目标版本是否兼容，先保留原始数据，再在隔离目录中验证。
