# FISH Dock 2.1.4

2.1.3 之后的补丁版：把 Windhawk 的残留设置面摘干净，修掉「挂了节点却还是走镜像、装得很慢」，并且插件下载失败时可以回退到的版本不再比你现在用的更老。

## 这一版改了什么

### 外观页不再有 Windhawk 设置面

2.1.3 只做到了「不再随包分发引擎」，外观页那段「Windows 美化 / Windhawk」还留着——里面是「未检测到 Windhawk，请先安装或指定目录」加三个折叠项，对一个已经不随包的功能来说只是噪声。

这一版把整段摘掉：设置面板里的渲染、挂载、加载、样式与脚本引用一并删除，`windhawk-panel.js` 不再打包进前端。外观页现在只剩壁纸与纸张两项。

> 说明：Rust 侧那套模组管理后端（状态读取、导入、启停、回滚）没有跟着删——它没有 UI 入口，也不会被调用；`retire_bundled()` 还要靠这个模块清旧文件。要彻底删干净属于另一件事，不塞进这个补丁版。

### 挂了节点却还是走镜像、装得慢（根因修复）

Dock 的网络请求走 `proxy::web_ways`。原来的判断是：

```
(Via::System, Some(系统代理)) if !env_proxy => 先系统代理，再 Default
(Via::System, _)                            => 只用 Default
```

`env_proxy` 是「进程环境里有没有 `HTTP(S)_PROXY`」。也就是说——**只要环境变量里残留一个代理值**（例如之前用过的内核地址、或者别的软件写进去的），Dock 就跳过 Windows 的系统代理，只让 ureq 按环境变量走。内核一关，那条环境变量就指向死端口：主源连不上 → 回退镜像 → 用户看到的是「明明挂着节点，还是从镜像慢慢下」。

现在改成系统代理优先、环境变量只当兜底：

```
(Via::System, Some(系统代理)) => 先系统代理，再 Default
```

显式配在 Windows 里的代理是人的意图，比进程环境更可信。`netProxy` 设成 `manual` / `none` 的行为不变，本机回环（`127.*`、`localhost`）仍然一律直连。

### 插件下载失败的回退不再「降级」

`#68` 的回退链是「目录当前版 → 历史版（新→旧）」，历史版来自随宿主发布的内置已验证表。问题是它只按「版本从新到旧」试，不看**你现在装的是哪一版**：用户已经从 2.1.6 升到 2.2.x、只是目录最新版暂时下不到时，一路退下去会装成 2.1.6——比升级前还旧，这是降级，不是回退。

现在回退有下限：`local_version()` 读 `installed-plugins.json` 里这个插件当前的版本，候选里低于它的版本一律跳过。目录当前版不受影响（它是最新，本来就该先试）。读注册表失败时不拦着装——把「读不到」变成「装不了」是更糟的错。

## 包与校验

- `FISH-Dock-Setup-2.1.4.exe`（完整安装包）
- `FISH-Dock-Update-2.1.4.exe`（精简差分包，**只对 2.1.3 有效**）
- 各自附 `.sha256`；`SHA256SUMS.txt` 列出全部。

2.1.2 起不来的问题在 2.1.3 已经修好，2.1.4 继承：若你的机器还停在 2.1.2，请用 Setup 覆盖安装。

## 已知限制

- 便携版入口仍无载荷（发行不提供便携 exe），安装版不受影响。
- 应用内更新只认 `FISH-Dock-Update-<版本>.exe` 与它的 `.sha256`；跨版本用精简包会缺文件。
