# FISH Dock 2.0.4

修订版。宿主为 **2.0.4**，兼容 **插件 2.1.x**（Clash 与 Magpie 2.1.3、飞书 2.1.0）；不是「宿主与插件同版本」。

这一版收 **#63、#65、#66、#67** 四条 issue，并回归 **#64**，主线是插件的两条链路——**自启**与**取资源**——
外加插件页交互与外链、Agent 会话 API、OFM 业务解耦与发布工程收口。

## 一、插件自启：一次尝试一份预算

旧实现的问题不是「慢」，而是**账算不清**：每个阶段各自计时、失败各自重试，重试预算还会层层叠加，
于是一台冷启动的机器上可能出现「clash / magpie 双超时、内置服务根本没被拉起」。

- 自启收进单一调度器 `plugin_start.rs`：**一次尝试共用一份预算**（冷启动 60 秒、热启动 10 秒），
  整轮生命周期 180 秒封顶，首次尝试加最多 3 次重试（0.5 / 2 / 5 秒），**最多两插件并发**。
- **每个插件同时只有一次在途**：在途 token 由 id、代次、版本、摘要组成；迟到的结果按代次丢弃，
  不会回填到新一轮卡片上。
- 到期仍未就绪的尝试记为失败并标 `late`，不再冒充成功；到期后不再开启新一轮。
- **备份暂停不再二次拉起**：暂停时把在途的插件一并 retire 并把代次推走，恢复后旧 worker 回来只能被丢弃，
  不再出现「后到的实例覆盖并杀掉前一个健康实例」。
- 失败分类拆成**永久**（清单/摘要/缺失、身份不符）与**瞬时**（读文件、元数据失败）：前者不重试，
  后者可重试，不再靠文案猜。
- worker panic 会被兜底回收槽位；手动启动成功后清掉本轮调度记录，卡片立刻跟实时状态。

## 二、资源获取：一层择源，一条总预算

- 新增 `sources.rs` 作为**唯一取资源层**：原站地址永远第一优先，镜像按配置作为候选，每条候选再按可用
  代理路重试；**候选 × 代理路共用一条总预算**，换路不重新放满时间。
- 落地只经**唯一临时文件 + 原子改名**；失败清掉半截文件，错误按「已试过哪些源、为什么失败」聚合上报。
- 更新包下载同样走这一层：镜像失败回原站，进度与「只保留当前版本」的语义不变。
- pet 的**列表、详情、立绘与预览改由宿主取回并缓存**，页面只拿本地 asset URL，不再自己外联。
- PawnIO 仍保留固定 SHA-256 与允许主机约束；LHM、Windhawk 沿用各自的校验与安装流程。
- Gitee 通道**配了才启用**；加速前缀默认为空。

> 说明：本轮**没有**为 pet、Release、Windhawk、LHM 找到可确认的免费国内镜像，因此「双源」目前是
> 「原站 + 可选镜像候选」的**能力**，不是「已配好两套源」。这一点在下面的「已知限制」里再列一次。

## 三、pet 的更新提醒

检查到宿主有新版本时，pet 会主动弹提醒，而不是只在设置页里等用户自己翻。

## 四、插件页：#63 交互与检索

- 「更多」从弹出菜单改成**整行可点的动作列表**：纵向两行、每行 32 px、行间发丝分隔，
  日志在上、卸载在下；卸载常态用危险色、悬停只加 8% 底色。
- 搜索框占位改为短句示例，命名规则移到说明行，长内容省略显示。
- npm 发现式检索补齐分页契约：后端返回 `total / filtered / hasMore / nextFrom`，
  前端按 `nextFrom` 推进；**短页**（如 20 条里只给 5 条）不再出现 0 → 20 → 40 这种跳号或死循环，
  被过滤的整页也会正常前进。

## 五、#67 插件页外链

插件页原来是 `sandbox="allow-scripts"`，没有 `allow-popups` 也没有 `allow-top-navigation`，
页面里任何 `<a href>`、`target=_blank`、`window.open` 都点不动。

- 采用**宿主受控通道**，不放开 iframe 沙箱：桥拦截 `a[href]` 点击（要求真实用户手势 `isTrusted`），
  把 http/https 链接交给宿主 `dock.open_external`；宿主先过页面票据，再复用既有的 URL 判定
  （只认 http/https、必须有主机、禁 userinfo、禁 NUL）后才调系统浏览器。
- `file:`、`javascript:`、`data:`、`vbscript:` 一律不拦也不打开；程序化调用需在用户激活窗口内；
  同一链接短时内重复点击会被节流。
- 通用 `FishDock.call('dock.open_external', …)` 被列入保留名单直接拒绝——否则脚本可以绕过手势与节流。
- 沙箱属性保持 `allow-scripts` 不变；服务页 iframe 的 `allow-popups` 是既有业务窗口，未改动。

## 六、Agent 会话 API 与 agent-core

- 新增本地 crate `agent-core`（只依赖 `serde_json`），承载中性事件与「消息 → 事件」投影；
  各 agent 的磁盘 I/O 仍在宿主。
- 新增 `/v1` 接口：`/v1/info`（免鉴权，可带 `proof` 防重放）、`/v1/sessions`（Bearer）、
  `/v1/events`（SSE，带 `epoch:seq` 游标与环形缓冲）。
- 隐私边界：`/v1` 用**独立投影**，恒不外露 `detail/step/reply/error/cwd`；关闭详情时清空历史环、
  队列与 replay，旧订阅收到 `reset` 后结束；所有响应带 `Cache-Control: no-store`。
- 资源上限：SSE 活跃写线程单独计数（≤8），慢客户端按真实 socket 写超时收回；退出时唤醒阻塞写。
- token 落在私有目录（Windows 按当前用户 SID 收紧并回读校验，Unix 0600/0700），轮换走临时文件 + 原子替换，
  失败保留旧 token。

## 七、OFM 解耦、命名清理与发布工程

- OFM 业务彻底解耦：判定集中到 `legacy_ofm.rs`，开发目录不再接受 `ofm`，旧网关插件走单一特判，
  安装器对退役载荷前缀硬拒；资源清单里 OFM 条目为 0。
- 活动上游命名迁移到新名，集成脚本、邮件集成与示例统一为 FISH Dock 命名。
- 配置收口到 `config.rs` 单一入口，新增键全部支持 `FISH_DOCK_*` 覆盖；旧前缀只读兼容。
- 发布工程：路径扫描同时覆盖 UTF-8 与 UTF-16LE；release 二进制不再内嵌本机构建路径
  （`env!("CARGO_MANIFEST_DIR")` 在 release 下为空），构建脚本不再在未设 vendor 目录时传空参。
- 对比度门禁回到 0 违规；`check-hardcoded` 与 `check-contrast` 均接入测试。

## 八、已知限制与未验项

以下项目**没有**在本次自动化里被证明，需要真机或后续确认，不应读作「已通过」：

- **真机 WebView2**：原生首帧时序、40 ms 决策窗口、审批气泡二次生长；插件页外链在真机上点开系统浏览器
  只验到「桥发出 → 宿主判定 → 调起接口」。
- **登录与开机自启**：真实登录流程与「开机后首次自启」需人工重启配合，本次未做。
- **升级与回滚**：2.0.3 的 Setup 包本体在本机缺失，只做了合成/隔离环境的升级链路验证。
- **免费国内镜像缺口**：pet、Release、Windhawk、LHM 均无已确认的免费国内镜像；Gitee 通道需自行配置。
- **`/v1` 的运行期细节**：`no-store` 原始响应头断言、「阻塞写中退出」的组合用例仍属补充验证项。
- **token 私有 ACL 的现场核验**：自定义数据根（`FISH_DOCK_APP_HOME` / `--data-root`）下的实际 ACL 回读
  需要在真机上确认一次。
- **Codex Desktop 内部请求现场**：分类与过滤按真实 rollout 字段实现，但未在 Desktop 发起内部请求的那一刻
  同时抓取 hook 与 rollout。
- **产品壳宽度**：固定 520 px 的产品壳在 480 px 视口下会横向溢出，属既有产品决策，本版未改。

## 九、安装与校验

| 安装包 | 使用场景 |
| --- | --- |
| `FISH-Dock-Setup-2.0.4.exe` | 首次安装、基础资源缺失或修复安装，包含完整离线运行时（约 312 MB）。 |
| `FISH-Dock-Update-2.0.4.exe` | 已有版本且基础资源完整时使用，只下载本次变更（约 30 MB）；缺失或损坏时提示改用完整包。 |

下载后请用同版本的 `SHA256SUMS.txt` 或包旁的 `<exe>.sha256` 核对摘要。
同版本号修订不会自动提示更新，请重新下载安装并核对最新摘要。
安装包当前未做 Authenticode 签名。
