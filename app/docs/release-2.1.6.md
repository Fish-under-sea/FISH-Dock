# FISH Dock 2.1.6

插件自启「第一次起不来」的根因修复，外加外观页残留的 Windhawk 设置面移除。

## 插件自启不再看运气

### 现象

开机或更新后第一次启动 Dock，Clash / Magpie 的自启经常失败，插件日志里是：

```text
[clash] 自启动准备失败：UNKNOWN 宿主调用超时
```

手动重开 Dock，或者点一次设置页，就好了。

### 根因

宿主把「插件 → 宿主」的存储回调排在响应队列里，**只有在等这个插件自己的回执时才顺手处理**。启动流程一结束就没有线程读插件的 stdout，于是插件在 `activate` 之后发出的每一次 `storage.read` / `storage.write` 都只能干等。冷态下 SDK 的宿主调用时限是 30 秒，等满就报「宿主调用超时」。

本机 2026-11-07 16:52 的那次启动把这条链钉死了：

| 时间 | 事件 |
| --- | --- |
| 16:52:43.809 | magpie 启动成功（`budgetCold:true`） |
| 16:52:43.810 | clash 启动成功 |
| 16:53:13.815 | magpie 第 1 次「宿主调用超时」 |
| 16:53:13.816 | clash「自启动准备失败：宿主调用超时」 |

同一毫秒两个插件一起超时，间隔正好 30.0 秒（宿主下发的 `hostCallTimeoutMs`）；随后两次重试的间隔 30.6 / 31.5 秒，又正好对上 `startWithBackoff` 的 600 / 1500 ms 退避。不是插件慢，是宿主在那 90 秒里一次都没读它们。

### 修法

`plugin_process.rs` 的读线程把带 `method` 的帧分给**常驻回调线程**：它在任何时刻都能执行 `storage_call` 并回写，不再依赖「宿主正好有一次在途请求」。`request` 与探针只等自己那条回执，回调不再参与它们的循环。

回归用例 `a_callback_is_served_while_no_request_is_in_flight`：让合成插件在 `activate` 返回 60 ms 后写一次存储，宿主全程不发请求。旧实现 3 秒轮询窗口内文件始终不出现，新实现 0.26 秒写入。

### 一次超时不再把插件打死

SDK 原来收到「编号已经作废」的迟到回执会直接抛错并关闭整个会话（`宿主响应编号不匹配` → `close()`），插件从此不再应答，宿主侧看到的是「插件响应超时」，只能重启进程。现在这类迟到回执直接丢弃，会话继续可用。

## 外观页不再有 Windhawk 设置面

2.1.3 起 Windhawk 引擎不再随包分发，那段「未检测到 Windhawk，请先安装或指定目录」的卡片对现有用户只是噪声。这一版把它整体移除：

- 删除 `windhawk-panel.js` 与 `index.html` 的脚本引用；
- 删除 `settings.js` 的创建 / 渲染 / 挂载 / 加载四处引用；
- 删除 `settings.css` 的 22 行（21 条规则 + 一行注释）；
- 删除 `windhawk-panel.test.js`，并在 `settings-order.test.js` 里钉一条反向断言：外观页的 Windows 分节不得再出现 Windhawk。

后端能力保留（`--windhawk-admin`、`retire_bundled()` 的旧引擎清理、配置备份规则都不动），只是界面上没有入口。彻底下线另开一项。

## 版本位

`tauri.conf.json`、`Cargo.toml`、`Cargo.lock`、Claude Code 插件清单统一为 2.1.6。

## 包与校验

- `FISH-Dock-Setup-2.1.6.exe`：首次安装、基础资源缺失或修复安装，含完整离线运行时。
- `FISH-Dock-Update-2.1.6.exe`：相对 **2.1.5** 的精简差分包；更早版本请用 Setup。
- 各自附 `.sha256`，`SHA256SUMS.txt` 列出全部。

## 已知限制

- 便携版入口仍无载荷（发行不提供便携 exe），安装版不受影响。
- 应用内更新只认 `FISH-Dock-Update-<版本>.exe` 与它的 `.sha256`。
- 插件侧的自启写法（准备阶段失败不进重试、`view()` 多次读盘）本轮没有改，已作为任务需求记进插件仓。
