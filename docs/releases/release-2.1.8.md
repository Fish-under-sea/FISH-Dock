# FISH Dock 2.1.8

**关掉 Clash 不再断网**：系统代理在五种退出方式下都会被还回去，崩溃后也有人替你修。
另外，精简更新包失败时不再是一句「更新未完成」就结束——它会自动取完整安装包覆盖安装。

## 为什么有这一版

2026-11-07 晚的现场：关掉 Clash 后整台机器没有网络。检查结果是注册表里

```text
ProxyEnable = 1
ProxyServer = 127.0.0.1:7895
```

而 7895 端口没有任何监听。四条路径各自都能造成它：

1. **停用被预算截断**：`service.stop()` 把「还系统代理」排在最后，宿主给 `plugin.deactivate` 的预算只有 5 秒，到点直接 kill 插件——注册表永远停在「指着刚死的端口」。
2. **看门狗跟着宿主一起死**：看门狗是 `spawn(detached)` 拉起的，但 Windows 上 Node 的 detached 不带 `CREATE_BREAKAWAY_FROM_JOB`，它仍在宿主给插件建的 Job 里；宿主一崩，Job 关闭，插件 + 内核 + 看门狗一起消失。
3. **崩溃后没有任何进程外的兜底**：崩溃钩子只写记录，`recoverStaleOnce()` 只在插件 `activate` 时跑，登录任务只负责启动 Dock。
4. **TUN 模式由 SYSTEM 服务托管**，服务独立于宿主，宿主崩了它还在把整机流量劫走。

## 修法：四层兜底

| 层 | 谁做 | 什么时候 |
| --- | --- | --- |
| L1 | 插件 | `stop()` 第一件事就是还系统代理，之后才收内核；结尾不再重复 |
| L2 | 宿主 | `Process::stop()` 在 kill 之前自己读租约：端口还在跑就不动，端口没了就写回原值 |
| L3 | 宿主 `--proxy-heal` | 登录时 + 每 5 分钟一次的计划任务，跑一次就退出 |
| L4 | 插件 | 已有的 `recoverStaleOnce()`（启动自愈）保留 |

判定顺序是结论的一部分，换顺序就会在「内核还在跑」时把代理关掉：

```text
没有租约            → 什么都不做（这是「没启动内核就不要开」的全部保证）
租约坏了            → 删租约，不动注册表
注册表不是我们那份   → 别人改过，删租约，不动注册表
端口还有人监听       → 内核还在，什么都不做
端口没人听           → 写回接管前的三键，删租约
写失败              → 保留租约，下次再试；被拒键名与 Win32 码进 host/proxy-heal.log
```

刚写下的租约（60 秒内）不删也不动：插件是「先落租约、再写注册表」，中间隔着一次 PowerShell，那一瞬间删掉它等于删掉正在进行的接管。

## 关掉 Clash 的五种方式

| 方式 | 谁还的代理 |
| --- | --- |
| 页面「停止内核」 | 插件（L1，最前面） |
| 插件卡「停用」 | 插件（L1）；停用预算从 5 秒提到 30 秒（`timeout.plugin_deactivate_secs`） |
| 退出 Dock | 插件（L1）+ 宿主（L2） |
| 强杀 Dock / 宿主崩溃 | 计划任务（L3，5 分钟内） |
| 强杀插件进程（Dock 还在） | 宿主（L2） |

关程序不会再等 30 秒：退出、丢弃迟到实例、启动失败清理走 6 秒的 `stop_quick`。

## 精简更新包失败时自动改用完整安装包

`updates.rs` 用 `/S` 静默拉起更新包后自己退出；事务失败时安装器只剩一句「更新未完成」，而那时已经没有任何能显示进度的界面了。这一版：

- 构建 Update 时把**同版本 Setup 的地址、摘要、字节数、发行页**写进脚本（摘要与字节数取自这次构建出来的 Setup 文件本身，不读发布页）；
- 失败分支改为：把兜底脚本复制到 `%TEMP%` → 起一个**独立于 WebView2** 的进度窗 → 下载 → 校验 → 启动 Setup 覆盖安装 → 本安装器退出码 0；
- 兜底窗口支持直连/系统代理两条路、断点续传、取消、重试、手动下载，日志落 `%TEMP%\fish-dock-update-fallback.log`；
- 没有 Setup 可回退时（只出 Update 的场合）不写兜底分支，仍是原来的提示。

## 插件侧（Clash 2.3.4 / Magpie 2.3.4）

- Clash：停止顺序、启动失败收尾、坏租约、半死内核预算、TUN 宿主租约、看门狗改「任务计划拉起的进程」（只在系统代理被接管期间存在，恢复/停用即注销，恢复完自删任务）。
  已在用 TUN 的用户需要重新点一次「安装 TUN 服务」：服务 exe 是安装时复制到 `ProgramData` 的，插件升级不会替换正在运行的那一份。
- Magpie（#47）：插件宿主被替换（换代理、更新、崩溃重启）时，provider 不再被说成「You removed it from magpie.」。仍在安装的插件 provider 报「插件重启中」且不提供「加回来」；`neartoken:relist` 也会取消隐藏，救回已经掉进去的记录。

## 更新包

仍以 **2.1.0** 为基线：2.1.0 到 2.1.7 的用户点「应用内更新」都能一次升上来。

## 已知限制

- `--proxy-heal` 的注册表写入先走原生 API，被拒时回退到 Windows PowerShell（插件走的就是这条）；两条都失败时保留租约并把原因写进 `host/proxy-heal.log`，等下一次或下次启动再试。
- 安装包的欢迎/完成页只改了文案，没有位图：`MUI_WELCOMEFINISHPAGE_BITMAP` 在本机 NSIS 3.13 上会让向导页编译失败（换成 NSIS 自带的 `win.bmp` 也一样），所以这一版不加图。
- Clash 的 TUN 看门狗要靠服务侧读取 `host.json`；服务没重装时仍是旧行为（只有内核看门狗）。
