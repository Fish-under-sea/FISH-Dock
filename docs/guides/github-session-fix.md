# GitHub 登录保持修复记录

日期：2026-10-27。状态：修复已合入 1.2.0 常规完整安装包与精简更新包。

## 已确认的原因

1. 设备登录原先仅保存 `access_token` 和 `expires_in`，忽略服务端返回的刷新令牌与刷新令牌有效期。访问令牌到期后，公开视图直接显示未登录，没有续期路径。
2. Star 记录有 24 小时有效期，但界面只在等待设备授权时轮询。Star 记录到期后，账号仍在本地，界面却退回笼统的登录／Star 提示，也没有自动复核。
3. 访问令牌返回 401 时，旧实现直接清空账号；没有尝试刷新并重试一次。

[GitHub 官方刷新文档](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/refreshing-user-access-tokens) 说明：启用到期用户令牌的 GitHub App，其访问令牌通常 8 小时到期，刷新令牌 6 个月到期。通过设备流生成的令牌续期不要求 Client Secret。刷新会轮换访问令牌和刷新令牌，旧的一对随即失效。

## 修复

- 保存访问令牌、刷新令牌、各自有效期及所属公开 Client ID。账号记录继续使用宿主 DPAPI 加密；公开视图仅返回账号名、验证状态、到期时间和是否需要续期等脱敏信息。
- 访问令牌临近到期或已到期但刷新凭据有效时，通过官方 `grant_type=refresh_token` 流程续期。新的一对凭据先保存，再继续个人身份与 Star 请求。
- API 401 可触发一次刷新和重试。明确的失效／撤销响应才结束对应授权；网络超时、服务错误、限流和格式异常不清空原登录资料。
- Star 验证时间与登录有效期独立。Star 待复核会自动检查；确认未 Star 时仍显示已登录，继续要求点亮和成功验证。
- 自动续期失败采用退避重试。关闭设置面板暂停该面板计时，不退出已保存账号；下次打开面板或调用官方插件时继续按需检查。
- 显式退出登录清理凭据；取消设备验证、解除临时锁定与退出登录仍为不同操作。

## 旧账号迁移

旧记录可以继续读取。旧版本没有保存刷新令牌，所以这些账号的既有刷新凭据无法从本地恢复；访问令牌到期后需要重新登录一次。新授权建立完整的续期记录后，后续自动刷新。过期、撤销或绑定到其他 OAuth 应用的刷新令牌仍需要重新授权。
